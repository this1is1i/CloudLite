# 验收记录

## 图标、扫描进度与网络重试（2026-11-19）

- 可执行文件此前没有图标：图标资源 `assets/cloudlite.ico`（6 个尺寸）一直没有被编译进去。现在 `build.rs` 会定位 Windows SDK 的 `rc.exe`（先查 PATH，再查 Windows Kits 的 `x64` 目录，取版本号最大者），把 `1 ICON` 资源编译成 `cloudlite.res` 并作为链接参数交给链接器；找不到 `rc.exe` 时只打印警告，构建仍然成功。窗口类改用 `LoadImageW` 读取该资源，`WM_SETICON` 同时设置小图标与大图标，任务栏和 Alt+Tab 都显示新图标。
- 扫描改为两阶段并行：先用一个线程遍历目录收集候选文件（期间状态栏显示已发现数量），再按可用 CPU 数（1–8 个线程）并行读取标签；主线程每 100 ms 收到一次进度。扫描在独立线程里进行，二维码轮询和界面不再被扫描阻塞。
- 列表与播放条之间新增 6 像素高的进度条，只在扫描期间显示；读取阶段显示已完成/总数，结束后隐藏。重复点击“重新扫描”在扫描进行中会被忽略。
- `cloud.rs` 对 8 处在线请求（账号、二维码密钥、扫码状态、搜索、歌单、歌单详情、歌曲详情、播放地址）加入传输层重试：最多 3 次，间隔 250 ms × 次数；只在连接、超时、TLS、DNS、连接重置等传输错误上重试，接口返回的业务错误不重试。
- 本次 `cargo test --offline --locked --tests` 23 项通过，`cargo fmt --check` 通过，Release 构建通过；可执行文件 3,602,944 字节（较上一版增加 46,592 字节，来自图标与资源）。用 `ExtractAssociatedIcon` 从新可执行文件中取出的 32×32 图标即为蓝色音符标识。
- 进度条动画、并行扫描在中大型曲库上的耗时改善，以及重试在真实弱网下的效果尚未人工复测。

## 随机播放新增（2026-11-19）

- 播放区新增“开启随机 / 关闭随机”按钮（控件 ID 118，位于上一首、播放、下一首之后），托盘菜单同步提供“开启随机播放 / 关闭随机播放”。状态写入 `settings.json` 的 `shuffle` 字段；旧配置文件没有该键时按关闭处理。
- 开启后每轮重新洗牌：候选集排除当前歌曲，Fisher-Yates 洗牌后逐首弹出，一轮内不重复；一轮结束后重新洗牌。上一首沿实际播放历史回退。随机算法使用 xorshift64，种子取自系统时间与进程号，未新增依赖。
- 关闭随机后恢复按列表顺序播放，到达队列末尾停止，并给出相应状态提示。
- 本次 `cargo test --offline --locked --tests` 23 项通过，新增 `shuffle_plays_every_track_once_per_pass_without_immediate_repeats` 与 `shuffle_previous_walks_back_and_a_single_track_stops`；`cargo fmt --check` 通过。Release 构建通过，可执行文件 3,556,352 字节（较上一版增加 2,048 字节）。
- 按钮点击、托盘菜单和随机状态在重启后的恢复属于界面行为，尚未在本次自动化中人工复测。
